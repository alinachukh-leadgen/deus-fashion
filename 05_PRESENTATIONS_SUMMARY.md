# 1. LAND'S END — INTRO, SEPTEMBER 30, 2026

## Purpose

This is a sophisticated first-conversation deck.

The central positioning is:
"Building around Dodgeville, not replacing it."

The deck is deliberately discovery-heavy. The introduction is kept under five minutes, and most of the meeting is devoted to understanding the operation.

Source: Deus Robotics × Lands' End — Intro, Sept 30 2026.

## Business understanding

The deck frames Lands' End as:
- multiple channels on one floor;
- US e-commerce;
- Outfitters serving more than 70,000 businesses/schools;
- retail and third-party flows;
- personalization through monogramming, embroidery and hemming;
- existing automation;
- a new Manhattan warehouse system.

The key strategic assumption:
the warehouse system stays in place; Deus adds an orchestration layer beneath it.

## Discovery logic

The deck asks:
- how work is split between buildings;
- what existing automation covers;
- what is still handled manually;
- where the operation hurts;
- what peak looks like;
- what success should mean in one year.

Then it asks:
- normal/promotion/peak orders;
- single-unit share;
- SKU count;
- personalization share and waiting time;
- pickers and shifts;
- temporary labor;
- returns;
- existing automation.

Then:
- Manhattan product/version;
- equipment control;
- appetite for another integration;
- decision makers;
- payback hurdle;
- capital vs monthly operating cost.

This is a model for consultative selling: understand the operation before prescribing the technology.

## Key message

The strongest product message is:
"Your warehouse system stays in charge."

Manhattan talks to Deus RMS once. Deus RMS schedules devices beneath it.

## Four "we would not do" rules

1. Do not replace/touch Manhattan.
2. Do not touch peak 2026.
3. Do not write off working automation.
4. Do not invent a payback.

These are excellent objection-prevention principles.

## Where robotics fits

The deck maps different flows:
- single-unit e-commerce → Shelf-to-Person;
- personalization → transport;
- Outfitters/bulk → picker-assist + transport;
- returns → Shelf-to-Person for restocking.

The key commercial lesson:
find the flow with the most walking.

## Personalization flow

Pick → personalize → check → pack.

Transport robots can move work between stations in the correct sequence.

Important detail:
Manhattan remains the source of instructions; Deus moves/tracks work.

## Reference economics

The deck includes:
- 24 shelf-carrying robots;
- 450 mobile shelves;
- 2 picking stations;
- $1,310,780 first-year reference configuration;
- $47,300/month over 36 months in the example;
- 36–60 month terms for US businesses;
- typical 1–2 year payback for this class, with the actual prospect number built from their data.

Use these as reference configuration economics, never as a generic quote.

## Timing philosophy

Nothing touches peak 2026.

Indicative path:
- Oct–Nov: questionnaire/floor plan/integration discussion;
- Dec: concept and priced proposal;
- Jan–Feb 2027: site review;
- after peak: first zone installed, trained and measured.

The key principle:
results before scale.

# 2. ROCKSTAR ORIGINAL — CONCEPT PROPOSAL, MAY 21, 2026

## Purpose

This is a deep technical/commercial concept proposal for a specific warehouse in Vernon, CA.

It demonstrates how Deus builds a tailored concept from actual operating inputs.

## Prospect profile used

- Vernon, CA;
- 2–3K / 6–7K / 35K daily throughput across low season / peak / Black Friday;
- average order size: 4 units;
- cartons around 24 × 14 × 14 inches;
- existing racks;
- iSync WMS;
- standard API integration.

## Architecture

Recommended concept:
STU + Q1P Tote-to-Person.

- STU shuttle robots operate vertical aisles;
- Q1P floor robots transport totes/cartons;
- Deus RMS orchestrates the fleet;
- iSync remains connected through the API;
- carton-direct handling is possible.

The concept is built around:
- 30,000 storage locations;
- 4 levels;
- 22 STUs;
- 60 Q1Ps;
- redundancy;
- 6 outbound and 2 inbound stations;
- 12,000 lines/day design target.

## Strongest technical selling points

1. Payload.
2. Storage density.
3. Redundancy.
4. Vendor-agnostic orchestration.
5. Fit to the client's physical cartons.
6. US-based support/control layer.

## Competitive positioning

The deck compares Deus with a Libiao proposal.

The useful sales lesson is NOT "trash Libiao."

Instead:
compare:
- actual delivered scope;
- payload;
- physical fit;
- storage architecture;
- safety;
- support;
- included/excluded scope;
- landed cost.

This is consistent with the playbook rule to let facts do the work.

## Commercial philosophy

The deck emphasizes DAP USA and transparent landed cost.

It distinguishes:
- factory/EXW headline pricing;
- freight;
- duties;
- rack modifications;
- installation;
- software;
- project delivery;
- support.

This is useful when a prospect is comparing Deus against a cheap-looking equipment quote.

## Closing sequence

Concept → NDA → close open inputs → ROI/payback → reference visits → final proposal/contract.

Important:
never treat the first concept as final.
Open assumptions must be explicit.

# 4. ROCKSTAR ROBOTICS VS ERP — JULY 2026

There are two uploaded versions with substantially the same strategic content.

## Central thesis

Warehouse robotics and ERP/WMS replacement are two different projects.

They should not necessarily be chained together.

## Comparison

Warehouse robotics:
- one warehouse;
- weeks to months;
- can pay for itself through operating savings;
- reversible zone by zone;
- if delayed, manual picking continues.

ERP/WMS replacement:
- touches the whole company;
- typically much longer;
- significant implementation cost;
- much higher organizational risk;
- difficult to reverse after cutover.

## Core architecture message

Deus RMS sits beneath the system of record.

Current ERP/WMS can run the floor.
A future ERP/WMS can later connect to the same RMS.

The robots do not need to wait for the ERP decision.

## Strong strategic argument

Doing robotics first can make the later ERP migration easier because:
- inventory gets physically verified;
- location structure becomes documented;
- warehouse process becomes stable;
- the company changes one major system at a time.

## Transition model

Today:
Current ERP/WMS → Deus RMS → robots.

During migration:
Old + new ERP/WMS can run in parallel by zone → Deus RMS → robots.

After:
New ERP/WMS → Deus RMS → same robots.

## Sales lesson

When a prospect says:
"We're changing ERP/WMS first, so robotics has to wait."

Do not argue about ERP.

Instead:
- separate the projects;
- explain that RMS is the bridge;
- explain that the warehouse can start producing savings sooner;
- show how robotics can support a cleaner later migration.
