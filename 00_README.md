# DEUS ROBOTICS — SALES & OUTREACH KNOWLEDGE BASE

## Purpose

This repository is the working knowledge base for Claude's Deus Robotics sales/outreach work.

Claude must use this repository together with the connected HubSpot data. The repository contains:
- the sales playbook;
- the outreach writing system;
- product and commercial knowledge extracted from the presentations;
- proven outreach examples;
- research rules;
- HubSpot activity rules;
- language and compliance guardrails.

The goal is to move a qualified prospect from research → relevant outreach → conversation → discovery → questionnaire → concept → reference → offer, while keeping every interaction human, evidence-based and properly logged.

## Source hierarchy

When information conflicts, use this priority:

1. Current client/prospect-specific facts from HubSpot and current research.
2. Current approved Deus materials in this repository.
3. The Apparel E-Commerce Sales Playbook.
4. Older presentation material, only where it has not been superseded.
5. Never invent missing information.

If a number, product capability, reference, timeline or commercial term is uncertain, flag it instead of guessing.

## Critical operating rule

Before ANY outbound email or LinkedIn message:

1. Search HubSpot for the contact/company and recent activity.
2. Check the last outbound email AND the last outbound LinkedIn message.
3. Treat an outbound message as spam if another outbound message was sent less than 14 days ago.
4. If the 14-day minimum has not elapsed, do not send a new outbound message.
5. Use HubSpot activity history to understand what has already been said.
6. Never repeat the same pitch, trigger or question if it has already been used.
7. Log every sent email and LinkedIn message in HubSpot on the same day.

The 14-day rule is the new operating rule and supersedes the older playbook cadence of Day 1 / Day 4 / Day 10 / Day 18 when those touches would violate the 14-day minimum.

## Core writing principle

Do not write from a template first.

Research first → identify the most relevant trigger/problem → choose one Deus capability that answers it → write a short message around that connection.

Personalization must be substantive. Do not use empty personalization such as generic praise, "I saw your website", or a fact that has no relationship to the operational problem.

## Proven example

The Capelli Sport outreach is a reference example because it received a reply and resulted in a meeting being scheduled. Use it to understand structure and positioning, not as copy to reproduce.

## Important product positioning

Deus is not presented as a robot box seller.

Core positioning:
- one party responsible for a working result;
- robots + mobile shelving + stations + software + WMS integration + deployment + training/support;
- vendor-neutral orchestration;
- existing systems and equipment can continue to operate;
- the platform is the control/orchestration layer;
- Shelf-to-Person removes picker walking;
- the commercial conversation is based on the client's own numbers.

## Do not

- invent facts;
- invent ROI/payback;
- promise integration timelines before engineering review;
- name restricted hardware manufacturers to clients;
- disclose confidential reference names without approval;
- send decks in cold emails unless requested;
- pressure prospects;
- contact a person more frequently than once every 14 days;
- log activity only later: HubSpot must be updated the same day.
